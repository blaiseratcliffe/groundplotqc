# groundplotqc 0.0.0.9020 (development version)

- First version: the package skeleton, with its help pages, tests, lint configuration, continuous integration on Windows, macOS and Linux, and the pkgdown site.
- `gpq_column_map()`, `gpq_type_map()` and `gpq_sentinels()` describe a specification's dictionary columns, its types and its missing-value codes. Two example specifications, a fish survey and forest ground plots, come with the package.
- Every specification CSV, read through `gpq_type_map()` or `gpq_read_spec()`, goes through one reader that records what it finds as findings about the file, an invalid byte or a malformed line. `gpq_type_map()` given a file, whose path must end in `.csv`, carries them as the attribute `gpq_read_findings`.
- The CSV reader also reports, as findings about the file, a warning from `data.table::fread()` that the package doesn't recognise, rows that were read short of the file's records after its header, and a quote that `fread()` stops on in a file of one column. It reports them whatever the session's `warn` option, so with `options(warn = 2)` a malformed CSV doesn't stop the read. The package needs data.table 1.18.2.1 or later.
- `gpq_read_spec()` reads a data dictionary, its code lists, translation tables, datasets table and lineage spec into one specification object, recording every defect it finds for pre-flight. A blank name in `non_code_sheets` is dropped, as a repeated one is.
- `gpq_preflight()` checks a specification before any data is read, with checks that stop or warn, a pre-flight CSV and a self-contained HTML report. It also takes a rule set, settings and report text (`rules`, `settings`, `text`): three more checks find rule-set rows that name an unknown table, attribute or rule, or give a rule a severity or class it can't take, each placed by its file and line where the rule set was read from files; no rule set or setting can change what a pre-flight check stops or warns on. The `text` rows and the `lang` setting are what pre-flight's report-text checks read; its own page and table stay in the package's English text. The options `groundplotqc.lang` and `groundplotqc.severity` are documented on `?groundplotqc_options`.
- Pre-flight checks that every registered rule has English report text and, in a run language other than English, lists each text that falls back to English; it stops on a text in the caller's table that uses a slot the package's row of that text doesn't have. The pre-flight page opens with a one-line result and an introduction that covers the run's configuration as well as the specification, its footer names the rule set that was checked when the rule set has a meta row, and its rows table's count column reads "Findings in this check".
- A first article, "Specification files and configuration", reads and pre-flights the fish survey example.
- `magp_spec()` returns MAGPlot 2.0's specification, compiled from 20261005_magpv2_DD.xlsx, 20261005_magpv2_Lookup_Tables.xlsx, 20261005_magpv2_A2.xlsx, 20261005_magpv2_datasets.csv, 20261005_magpv2_species.csv, 20261005_magpv2_condition.csv, 20261015_magpv2_treatment_disturbance.csv and 20261005_magpv2_severity.csv.
- `magp_rules()` returns MAGPlot 2.0's rule set: its meta row, its rules rows and its settings, compiled from the hand-kept files in `data-raw/magp/` for the 20261005 specification files.
- `magp_example` is a small synthetic example of MAGPlot 2.0's 17 tables, built from `magp_spec()`: every table and column of the data dictionary, with made-up values. Help pages use it.
- The pre-flight CSV, `metadata/preflight.csv`, ends its lines with LF on every platform, so its bytes are the same on Windows, macOS and Linux.
- Five settings for the conformance checks, each also an option (`?groundplotqc_options`): `example_cap`, `column_level_min_n`, `raw_na_policy`, `rogue_codes` and `unknown_codes`. In a rule set's settings rows a whole number has type `integer`, several values are joined by "; " and a named value is written "name=value". MAGPlot 2.0's rule set raises a raw `NA` as an error everywhere outside the keys and treats `UNKN.SPP` in `species` as an unknown code.
- A rule set's `rules` rows give a rule's severity and turn it off by table and attribute; the most specific row that gives a value wins. Pre-flight's new check `rule_set_duplicate_row` stops on two rows that name the same rule, table and attribute.
- A rule set component edited, reordered or filtered after it was read no longer names its file's lines in pre-flight's findings, which give R's row numbers instead.
- `gpq_check_conformance()` checks a set of tables against a specification and returns the results summary and the issues, after running pre-flight on the specification and configuration. Layer 0 finds tables and columns missing, unexpected, or named with other letter case or spaces than the data dictionary's; Layer 1 finds a column stored as another type, values its type can't hold, dates that aren't real dates in their format, and NaN or Inf in numbers; Layer 2 finds a missing value written as NA, a blank, another type's missing-value code, a placeholder such as -999, a code for unknown, an ID that is the text NA, and spaces around a code or an ID. A value that failed an earlier layer isn't checked again: its issue there is not evaluated and names the first issue. A rule that fails on every checked record of a column in a group, when at least `column_level_min_n` were checked, is recorded as one column-level issue. A column stored as integer64, as a DBI query returns a BIGINT column, now has its missing-value, rogue and unknown codes recognised as in any number column: `sentinel_wrong_type`, `sentinel_rogue_code` and `species_unknown_code` report them (now rule version 2), and Layer 4 reads such codes in a key as missing-value codes, not as key values. When such a column is a table's primary key and a key repeats, every record holding it is now marked positional in the issues (`pk_positional`), the first one included. When a table holds such a column, as `readRDS()` can return one in a session where bit64 isn't loaded, the run now loads bit64, and stops if it isn't installed. Before, such a column was read as plain numbers without a warning, so its codes, keys and values could be reported wrongly. A composite primary key's repeats are now found exactly in a session that has raised data.table's `setNumericRounding()`, so every record holding a repeated key is marked positional. In a number-typed column stored as integer64, a value a double can't hold exactly (above 2^53) now fails `coercion_loss`, and as a key it joins no other record, as parent or child. Before, such a key could join the wrong record.
- `gpq_write_results()` writes a run's results to its folder, the tables to `tables/` and the run metadata to `metadata/`, and `gpq_read_results()` reads them back identical. A run's files are written once: a run folder holding any file but that run's own pre-flight files is refused.
- `gpq_check_conformance()` also reads its tables from CSV files: give a path in place of a data.frame, or a named character vector of paths. Every column of a CSV file is read as text, as written, an empty cell as a missing value; a cell that isn't UTF-8 is read as Windows-1252 where Windows-1252 defines its bytes, and the separator is found from the file. A file that can't be read cleanly stops the run before any check. The run's inputs metadata records each file's name and SHA-256.
- `gpq_check_conformance()` also reads its tables from a DBI connection, such as a database's: its new third argument `table_map` gives the database's name for a table it names otherwise, `"schema.table"` for a table in a schema. Only the specification's tables are read. DBI and RSQLite join Suggests.
- A conformance run's fixed cost is cut: a run on `magp_example` takes about a third of the time it did, with the same results and issues.
- A second article, "Using the engine on your own dataset", checks the fish survey example as data frames, as CSV files and from a database, and writes its results to a run folder.
- `magp_spec()` accepts NO as a `treatment_type` code and ND as a `disturbance_type` code: it is compiled from 20261015_magpv2_treatment_disturbance.csv, which gives NO's `treat_vs_dist` as T and ND's as D, in place of the 20261005 copy.
- `gpq_check_conformance()` accepts CSV paths given as a classed character vector, such as `fs::path()` returns, whether as `tables` itself or as an element of it, and `table_map` given that way; each is read as its text.
- A CSV file that changes while `gpq_check_conformance()` reads it stops the run before any check.
- `gpq_column_map()` names eight more dictionary columns, `min_value`, `max_value`, `min_inclusive`, `max_inclusive`, `pattern`, `max_length`, `decimals` and `units`, read into the specification's `attributes`. Pre-flight's new check `dd_format_invalid` stops on a cell in them that doesn't read or doesn't fit its attribute's type, and on a minimum above its maximum.
- The fish survey and forest examples' dictionaries give ranges, patterns, lengths, decimal places and units, under their own column names.
- `magp_example` follows MAGPlot's data dictionary more closely: its numbers are within the dictionary's ranges, each site's ID is in its contributor's band of site IDs, the `ec_*` columns match their patterns, each plot's subplots are labelled as its design's frames, and each value a record repeats from its parent agrees with the parent's.
- A results row for a group in which the rule checked no record, each masked by an earlier issue or not checked by the rule, now has status `not_run` with reason `none_checked`, where it read `pass`. On a table with no rows, a rule that checks records writes one `not_run` row per column, reason `no_records`, where it wrote `pass`. Both apply to the rules of Layers 1 and 2 too.
- Layer 3, value domains, starts: `code_not_in_list` finds a coded value that isn't in its code list, whether the list is a sheet of code lists or a translation table. bit64 joins Suggests.
- Layer 3 checks values against the data dictionary's ranges, lengths, patterns and decimal places (`value_below_min`, `value_above_max`, `string_too_long`, `pattern_mismatch`, `decimals_exceeded`), and the coordinates the new setting `coordinate_attributes` names against their ranges (`coordinate_out_of_bounds`), set as an option too. A rule whose dictionary column is blank for every attribute it checks writes one `not_run` row, reason `no_dd_values`, and `coordinate_out_of_bounds` without the setting one with reason `no_input`. MAGPlot 2.0's rule set names `latitude`, `longitude`, `utm_e` and `utm_n`.
- A foreign key that is empty or only spaces, Unicode spaces included, no longer leads a record to a parent whose primary key is blank too, so the record's group values through it are "*".
- `site_id_out_of_range` checks each site's ID against its contributor's band of site IDs. `gpq_read_spec()`'s `id_bands` takes the banded column (`table`, `attribute`) and the chain of foreign keys to the band's key (`key`); the specification gains the component `id_band_columns`, and `id_bands` the column `key_value`. A site that reaches no band isn't checked, and pre-flight's `site_id_range_invalid` also stops on a banded column the dictionary lacks, a key it can't follow, or more than one band for a value of the key.
- `undeclared_code_set` warns once on a text column without a code list that holds more than `code_set_max_values` values (built in 25) but no more than that many distinct ones, as a list of codes would; keys and IDs aren't judged, nor the attributes `code_set_skip_attributes` and `code_set_skip_pattern` name. MAGPlot 2.0's rule set skips IDs, source attributes, names, dates, comments and six attributes by name.
- Pre-flight and conformance runs start faster: the list of registered rules is built once per R session, not at every call.
- Layer 4, keys and relationships, starts: `pk_duplicate` and `pk_missing` check each table's primary key, `fk_orphan` and `fk_unassigned` each foreign key, `fk_sentinel_unverified` warns of a number foreign key holding a missing-value code it may hold, and `fk_not_applicable_mismatch` doesn't run until a later version brings the applicability matrix. A key of only spaces, Unicode spaces included, counts as blank in a number-typed or date-typed key too, so `pk_missing` or `fk_unassigned` reports it, not `coercion_loss` or `date_unparseable` (now rule version 2). A key that fails a Layer 3 check, such as a site ID outside its contributor's band, is still checked as a key by Layer 4.
- `gpq_read_spec()` takes `key_pairs`: pairs of ways to reach one value from a record, which pre-flight checks (`key_pair_invalid`) and `key_incoherent` compares. MAGPlot's 21 pairs are in `data-raw/magp/key_pairs.csv`.
- `src_id_duplicate` warns of an ID outside the keys (an attribute `id_pattern` marks, MAGPlot's `src_*_id`) held by more than one record of a table in one report unit. `gpq_read_spec()` takes `one_to_many`, the IDs a contributor documents as one-to-many, which `src_id_duplicate` leaves alone for that contributor's records and pre-flight checks (`one_to_many_invalid`, a warning: a row pre-flight can't apply is left out). MAGPlot's come from A2's sheet `one_to_many` once A2 has one.
- `record_unreachable` reports a record that no walk from the root reaches through its keys, the walk given by `gpq_read_spec()`'s new `reach` input, which pre-flight checks (`reach_invalid`). MAGPlot's walk starts at the site visits; its unreached designs and trees are warnings. `parent_without_children` counts, with no issue, the parent records no child record names.
- A key holding NA, NaN, a blank or a missing-value code never leads to a parent record, whatever codes the parent's key holds. Before, a NaN key joined a parent's NaN key, and R's `match()` let some of the others through, depending on the values and the R session, so a record's group values and the counts of the rules that follow keys could change from run to run.
- Pre-flight checks the tables and attributes that settings name: `unknown_codes`, `coordinate_attributes`, `code_set_skip_attributes` and the eight settings of the three design checks. A name the specification lacks stops pre-flight when given as an argument or in a rule set (`setting_unknown_name`); set as an option, which applies to every specification checked in the session, it warns (`option_unknown_name`) and is ignored. A value of the wrong shape for one of these settings now stops `gpq_preflight()` as well as `gpq_check_conformance()`.
- Layer 4 checks plot designs, each check reading its table and columns from new settings, which MAGPlot's rule set gives: `design_geometry_inconsistent` (records of one group that disagree on a value), `subplot_label_ambiguous` (records of different keys with the same labels) and `design_duplicate_signature` (records of one report unit with the same rows in another table, a warning).
- `gpq_preflight()` stops on a dictionary row whose table or attribute name is missing, empty or only spaces (`dd_name_missing`).
- `gpq_read_spec()` gains `lineage_when`, conditions under which a part of a source ID is read from another provider column, and `lineage_separator`, the text composite IDs join their parts with; the lineage spec gains the columns `when` and `separator`, and pre-flight checks the conditions (`lineage_when_invalid`). `magp_spec()` gives Ontario's age trees and vegetation subplots their own provider keys.
- New `gpq_decode_lineage()` shows each record-level issue in the provider's terms: the record's source ID, read from the tables at the issue's row, split into the parts its contributor's lineage spec expects, each labelled with the provider's table and column (`provider_key`), with a status saying how far it decoded (`provider_key_status`); an issue's fingerprint is taken from the provider key where that key is unique. It stops if the tables aren't the ones the issues came from.
- `gpq_preflight()` takes the run's optional inputs, `inputs`: `overrides`, `lineage` and `pipeline_fill`, each a data.frame or the path of a CSV file. It stops on an input it can't read cleanly or without exactly its columns, and on an override whose class isn't source or harmonization or that gives no scope (`input_unparseable`); it warns on two overrides that give one scope two classes (`override_scope_conflict`) and on an override naming a rule, table or column it doesn't know (`override_unknown_name`).
- The setting `fallback_class` (option `groundplotqc.fallback_class`) gives, by rule, the class of an issue whose rule's class is `depends` when nothing else settles it. The tier that gives it gives all of it, replacing the lower tiers' entries. Pre-flight stops on a rule it names that isn't registered (`rule_id_unknown`).
- New `gpq_classify_issues()` gives each issue its class (`issue_class`) and what decided it (`class_basis`): its rule's class, from the rule set's `rules` rows or the registry; your overrides, the most specific matching row winning and two that disagree leaving the issue unclassified, an override of a renamed or split rule applying to its new rules; and, for an issue whose rule's class is `depends` that nothing else settles, the rule's `fallback_class`, else `unclassified`.
- `gpq_classify_issues()` reads its evidence for issues whose rule's class is `depends`: `computed`, columns the pipeline computes; `filled`, cells its missing-value fill wrote; and, for code issues, `lineage`, the provider's raw values, with `crosswalk`, each provider code and the code it is translated to. Each settles an issue as harmonization.
- MAGPlot's configuration gains `pipeline_computed.csv`, the attributes MAGPlot's processing scripts compute for every record, and `crosswalk_provider_columns.csv`, the translation-table columns that hold each jurisdiction's provider codes; the build checks every row of both against the specification before it copies them.
- The article "Using the engine on your own dataset" ends with the fish survey's issues classed by an override and a `computed` row.
- A record whose shortest path of keys to a group column breaks on a missing, blank or missing-value-code key or value, or a table not given, tries the next path, shortest first, so fewer records are grouped under "*"; a key that names no parent record still gives "*".
- Results gain `n_unchecked`, the records a rule never reached; `n_not_evaluated` now counts only records a rule reached but didn't evaluate.
- `parent_without_children`'s not-run row now counts the parent table's rows when the parent's key column, or the child's table or key column, isn't given, and no records when the parent table isn't given. A parent whose key is missing or failed an earlier check counts as not evaluated (`rule_version` 2).
- `undeclared_code_set` writes one issue per report unit, each holding only that unit's values; values from records with no unit go in a row of their own, under "*" (`rule_version` 2).
- Issues gain `reaches_other_unit`, TRUE where an issue holds a value read from a record of another report unit, or from a record whose report unit is "*": a group value or the problem unit's key reached through the keys, a side that `key_incoherent` compared, or one of `undeclared_code_set`'s values from records with no unit. It isn't part of the fingerprint. Run folders written by earlier versions lack it and `n_unchecked`, so `gpq_read_results()` can't read them.
